# как растёт этот репозиторий

s26-lab — публичная витрина лабы, которая наполняется по мере её развития. репо не пишется разом: после каждой открытой сессии сюда добавляется то, что можно показать публично. этот файл описывает, как именно.

## принцип: публичное отделено от приватного

рабочий контекст лабы (переговоры, договорённости, личные данные участников и спикеров) живёт в приватном рабочем пространстве. в этот репозиторий попадает **только публичная проекция**.

**граница публикации задаётся происхождением материала.** Разрешены официальный сайт, опубликованные записи эфиров, уже опубликованные материалы автора и отдельное явное согласие автора. Сам факт наличия текста на другом публичном URL не подтверждает корректность его происхождения.

Закрытые сессии агентов, личные vault, файловая история, CRM, переписка, внутренние документы и их пересказ не используются как источник. Это относится и к обезличенным деталям: точные размеры, счётчики, даты, сбои и сочетания фактов могут идентифицировать человека или раскрыть устройство его системы.

| попадает в репо | остаётся приватным |
|-----------------|---------------------|
| программа: шесть элементов, недели, форматы, исходы | цены, пакеты, условия оплаты |
| принципы и методология из разрешённого публичного источника | контакты, личные хендлы, уникальные характеристики личной системы |
| обезличенные скиллы (без ключей и личных путей) | статусы переговоров, внутренние договорённости |
| проводники, уже заявленные на сайте (имя + роль) | неподтверждённый состав, не показанный публично |
| артефакты публичных сессий после проверки происхождения | сырые транскрипты, закрытые сессии агентов, личные данные и их пересказ |

У каждого нового материала в PR должны быть указаны:

- публичный источник или ссылка на зафиксированное согласие;
- автор, который проверил финальный текст;
- подтверждение запуска `scripts/privacy-check.sh`;
- подтверждение, что в материале нет сведений из закрытых сессий, vault, CRM, переписки и файловой истории.

## куда что класть

| папка | содержимое |
|-------|------------|
| `program/` | программа, шесть элементов, недели, ритм, карта подходов, проводники |
| `principles/` | принципы работы лабы |
| `streams/` | открытые эфиры (публичная сборка) |
| `skills/` | обезличенные скиллы-методологии |
| `glossary/` | термины лабы |
| `artifacts/` | артефакты сессий |
| `assets/` | shaper-диаграммы + `shaper.css` |

## стиль

все артефакты — в эстетике **shaper** (см. [`STYLE.md`](STYLE.md)): чёрно-белый технический язык, моноширинный шрифт, строчные буквы, рамки 1px, инверсия как активное состояние. новый артефакт делается по шаблону из `assets/` — так весь репозиторий читается как единая система.

## как контрибьютить

репозиторий публичный:
- **форк → правки → pull request** — работает сразу, без ожидания доступа;
- участники и проводники лабы с прямым доступом могут пушить в ветку и открывать PR.

перед каждым добавлением запускается `scripts/privacy-check.sh` и проверяется происхождение материала. Обезличивание само по себе недостаточно: уникальные цифры, даты и описания инцидентов тоже требуют публичного источника или согласия.

## как проводнику принести свой блок

репозиторий держит публичную версию программы. полная версия живёт в рабочем vault лабы, сюда попадает проекция. каждый проводник может положить свой материал сам — доступ на запись выдаётся по запросу, github указан рядом с именем в [`program/`](program/).

### что имеет смысл принести

| что | куда | пример |
|-----|------|--------|
| **шаблоны, которые участник забирает себе** | `artifacts/<ваш-слаг>/` | [`kirill-system/`](artifacts/kirill-system/) — восемь markdown-файлов, каждый работает после копирования в чужой vault |
| **рабочий инструмент: плагин, скилл, команда** | `artifacts/<ваш-слаг>/` | [`flow-compass/`](artifacts/flow-compass/) — плагин с четырьмя командами и шестью фреймворками |
| **методология без личных данных** | `skills/<имя>/` | [`skills/research/`](skills/research/) |
| **схема к разделу, у которого её нет** | `assets/` | по правилам из [`STYLE.md`](STYLE.md), html-исходник рядом с png |

### формат

**markdown-шаблоны, которые каждый может забрать и адаптировать под себя.** это единственное требование к форме: файл должен работать, когда его скопировали в чужой vault и заполняют своим.

- один файл — одна вещь, самодостаточно;
- пустые места для заполнения оставляем видимыми;
- личное вычищаем, оставляем механику;
- строчные буквы и en-dash «–» в служебных текстах, общий стиль репозитория.

### как положить

**форк → правки → pull request** работает сразу, без ожидания доступа. с прямым доступом — ветка и PR. агенту можно продиктовать задачу голосом: практика показала, что артефакт из восьми файлов собирается за время одного эфира.

перед каждым добавлением — `scripts/privacy-check.sh`, проверка публичного источника и ручная проверка владельцем материала.

### кто принимает

черновик собирает кто угодно — человек или агент. **принимает всегда человек.** это тот же принцип, по которому работает сама лаба, см. [`principles/`](principles/), пункт «человек в контуре».
